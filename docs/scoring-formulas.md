# 紧急度与置信度：公式、变量及详细计算过程

本文依据 2026-09-10 当前代码的 v2 评分实现。所有使用率以小数计算，例如 80% 写成 `0.8`。分数范围均为 `0～100`，不是预测正确概率或故障概率。

## 1. 两种分数的用途

| 分数 | 表示什么 | 何时计算 | 是否影响执行 |
| --- | --- | --- | --- |
| 紧急度 | 扩容的容量压力，或缩容的资源回收机会 | 读取资源 API 时根据建议及统计重新计算 | 用于排序，不单独授权执行 |
| 置信度 | 扩缩容建议的信号证据强弱 | 生成预测建议时计算并保存 | 建议执行要求高置信度，还要通过其他门控 |

“校准与验证”功能已删除，不参与这两个分数。RMSE、MAE、MAPE、历史测试达标率也不直接进入下面的评分公式。

## 2. 输入变量及默认参数

### 2.1 统计变量

评分使用入选模型的**未来预测序列**统计。页面历史观测 P95 可能与这里的预测 P95 不同，不能直接拿历史显示值代入评分。

设预测序列为 `y[0] ... y[n-1]`：

| 符号 | 代码字段 | 取值及计算方式 |
| --- | --- | --- |
| A | avg | `sum(y)/n`，预测均值 |
| Q | p95 | `numpy.percentile(y,95)`，默认线性插值 |
| K | peak | `max(y)`，预测峰值 |
| V | valley | `min(y)`，预测谷值 |
| G | gap | `K-V`，峰谷差 |
| H | high_ratio | `数量(y≥0.8)/n`，默认高负载比例，范围 0～1 |
| L | low_ratio | `数量(y≤0.2)/n`，默认低负载比例，范围 0～1 |
| Nlow | low_streak | `y≤0.2` 的最长连续点数，不要求出现在序列末尾 |
| s | slope | 对全部预测点，以点序号 `0...n-1` 为 x 做一元线性拟合的斜率 |
| d | window_mean_delta | 末窗口均值减首窗口均值，详见下式 |

```text
s = Σ[(i-平均i)×(y[i]-A)] / Σ[(i-平均i)²]
w = max(2, min(trend_window_points, n//2 if n≥4 else n))
d = mean(y[-w:]) - mean(y[:w])    当 n≥2w
d = y[-1] - y[0]                 当 2≤n<2w
s = d = 0                       当 n<2
```

默认 `trend_window_points=6`。斜率单位是“每预测点的使用率变化”，不是每小时变化；预测步长会影响其含义。高低负载比例默认使用固定的 `0.8/0.2`，不会随着策略层级阈值一起平移。

VM 使用 CPU、内存、磁盘。K8S 使用 CPU、内存，扩容证据取 Limit 使用率，缩容证据取 Request 使用率；当前规格在 `spec.containers` 中按容器保存。缺规格、绝对使用量口径及无有效数据会影响建议能否产生，不能把绝对核数直接当作百分比代入。

### 2.2 策略阈值

以下为默认配置经过 `policy_thresholds()` 转换后的实际值；资源具体使用哪一列，以建议中的 `policy_tier` 为准。

| 符号 / 参数 | conservative | balanced | aggressive |
| --- | --- | --- | --- |
| To：CPU/内存扩容阈值 | 0.75 | 0.80 | 0.85 |
| Tp：CPU/内存峰值保护阈值 | 0.80 | 0.85 | 0.90 |
| Ta：缩容均值阈值 | 0.15 | 0.20 | 0.25 |
| Tq：缩容 P95 保护阈值 | 0.30 | 0.35 | 0.40 |
| To：VM 磁盘扩容阈值 | 0.70 | 0.75 | 0.80 |
| Tp：VM 磁盘峰值保护阈值 | 0.75 | 0.80 | 0.85 |

磁盘基础扩容和峰值阈值为通用值减 `0.05`。conservative 再减 `0.05`，下限 `0.01`；aggressive 加 `0.05`，扩容/峰值上限 `1.5`、缩容阈值上限 `0.95`。磁盘缩容评分使用通用 Ta/Tq。

| 其他参数 | 默认值 | 用途 |
| --- | --- | --- |
| consecutive_high_threshold | 0.8 | H 的判定阈值 |
| consecutive_low_threshold | 0.2 | L、Nlow 的判定阈值 |
| uptrend_slope_threshold | 0.012 | 上升斜率归一化分母 |
| downtrend_slope_threshold | -0.012 | 下降斜率归一化分母取绝对值 |
| window_mean_delta_threshold | 0.08 | 首尾窗口均值差归一化分母 |
| peak_valley_gap_threshold | 0.3 | VM 尖峰扣分分母；K8S 此处分母固定为 0.3 |
| 短历史默认门槛 | 120 小时，即 5 天 | 非 hold 建议置信度封顶 71 |

### 2.3 通用函数

```text
clip(x) = max(0, min(1, x))
clip100(x) = max(0, min(100, x))
I(条件) = 条件成立取1，否则取0
```

## 3. 紧急度计算

### 3.1 扩容：容量风险

```text
P = clip((Q-To) / max(1-To, 0.001))
E = clip((K-Tp) / max(1-Tp, 0.001))
B = 40 × I(Q≥To 或 K≥Tp)
Uout = B + 60 × max(P, 0.75×E)
```

逐步计算：

1. 确定当前指标的 To/Tp，磁盘使用专用阈值。
2. 用预测 P95 得到压力 P，用峰值得到压力 E，分别限制在 0～1。
3. P95 或峰值触及阈值，基础分取 40，否则取 0。恰好等于阈值也给基础分。
4. 峰值压力乘 `0.75`，与 P95 压力取较大者，再乘 60。
5. 加上基础分，单指标结果保留 3 位小数。

因此恰好触阈但未超过时可得 40 分；达到饱和时最多 100 分。超过 100% 不再继续增加紧急度。若扩容仅由趋势等其他条件触发而 Q/K 均未触阈，这个紧急度公式可以得到 0。

### 3.2 缩容：节省机会

```text
Ha = clip((Ta-A) / max(Ta, 0.001))
Hq = clip((Tq-Q) / max(Tq, 0.001))
F = min(Ha, Hq)
Uin = 60×F + 25×clip(L) + 15×R
```

| 项 | 取值范围 | 含义 |
| --- | --- | --- |
| 60×F | 0～60 | 均值与 P95 两种空闲度取较小者 |
| 25×clip(L) | 0～25 | 低负载预测点比例 |
| 15×R | 0～15 | 目标规格可回收比例 |

VM 的回收比例：

```text
Rd = clip(1 - target_spec[d]/spec[d])
R = max(有效 Rd)，没有有效维度时为0
d ∈ {cpu_cores, memory_gb, disk_gb}
```

当前值、目标值都必须为有限正数。目标未提供的 VM 维度不计入 R。

K8S 的回收比例：

```text
q = 目标副本数 / 当前副本数
Rd = clip(1 - q×Σ容器目标值[d]/Σ容器当前值[d])
R = max(有效 Rd)，没有有效维度时为0
d ∈ {cpu_request_cores, cpu_limit_cores, memory_request_gb, memory_limit_gb}
```

当前副本优先取 `spec.replicas`，否则取 `replicas_observed`；当前与目标副本不能同时取得有效正数时，代码使用 `q=1`。某容器某字段没有目标时沿用当前值；某个维度内任一容器的当前值或目标值无效，该维度不参与。CPU 和内存不相加，R 也不代表节约费用百分比。

例如同一 CPU Request 维度，两个容器当前合计 `1+0.5=1.5C`、目标合计 `0.5+0.25=0.75C`，副本从 4 变为 3：

```text
q = 3/4 = 0.75
Rd = 1 - 0.75×0.75/1.5 = 0.625
若其余维度回收比例均不大于0.625，则 R=0.625
回收项 = 15×0.625 = 9.375分
```

### 3.3 资源汇总与特殊值

只考虑与主动作同方向的有效指标。K8S 优先遍历 `container_advice`，缺容器建议时回退到资源 `stats`。每项 A/Q/K 必须为有限非负数；提供 `sample_count` 时必须大于零。

```text
资源紧急度 = max(同方向各指标、各容器的紧急度)
```

不累加多个指标，不加置信度、执行就绪或风险画像奖励。`components` 保存最高项的分解，`metric_scores` 保存各指标分数；同分时保留先遇到项的分解。

| 状态或分数 | 显示 |
| --- | --- |
| hold | 无需调整，0 分 |
| 无有效指标、无法识别方向 | 待评估；排序值为0，不代表低风险 |
| 0≤U<40 | 低 |
| 40≤U<70 | 中 |
| 70≤U<90 | 高 |
| 90≤U≤100 | 容量风险显示“紧急”，节省机会显示“极高” |

混合信号通常仍有扩容主动作，紧急度按该主动作计算；如果动作字段本身就是无法识别的 `mixed`，返回待评估。

## 4. 单指标置信度计算

### 4.1 超阈强度与空闲度

先令 `t=max(阈值,0.001)`。VM 与 K8S 共用以下超阈强度定义：

```text
above(x,t) = 0                                      当 x≤t
above(x,t) = min(1, (x-t)/max(1-t,0.001))             当 t<x≤1
above(x,t) = 1 + min(1, ln(1+x-1))                   当 x>1 且 x>t
below(x,t) = clip((t-x)/t)

p = above(Q,To)
k = above(K,Tp)
a = above(A,To)
ha = below(A,Ta)
hq = below(Q,Tq)
```

超阈强度最多为 2。公式中一般只使用 `min(1,强度)`；只有 VM 扩容额外使用 P95 强度超过 1 的部分。代码的自然对数写法为 `log1p(x-1)`。

### 4.2 趋势、稳定性和扣分

```text
Tu = 0.5×min(1,max(0,s)/max(0.012,0.0001))
   + 0.5×min(1,max(0,d)/max(0.08,0.0001))

Td = 0.5×min(1,max(0,-s)/max(abs(-0.012),0.0001))
   + 0.5×min(1,max(0,-d)/max(0.08,0.0001))

S = max(0, 1-min(1,G/max(Tq,0.001)))
上涨惩罚 = 12×Tu

尖峰惩罚 J = 18×min(1,G/max(g0,0.001))   当 k>0 且 p<0.15
尖峰惩罚 J = 0                          其他情况
```

Tu/Td/S 正常范围为 0～1；上涨惩罚最多 12 分；尖峰惩罚最多 18 分。Tu/Td 中的 `0.012/-0.012/0.08` 是默认参数值，修改配置后用配置值替换。VM 的 g0 取 `peak_valley_gap_threshold`，默认 0.3；K8S 固定为 0.3。尖峰条件使用未经 `min(1,...)` 截断的 p/k。

### 4.3 VM 扩容

```text
Cvm_out = clip100(
    42×min(1,p) + 20×min(1,k) + 14×min(1,a)
  + 16×clip(H) + 8×Tu
  + 8×max(0,p-1) - J
)
```

最后的 `8×max(0,p-1)` 为超饱和奖励，最多 8 分。

### 4.4 VM 缩容

```text
Bstreak = 8×min(1,Nlow/12)    当 Nlow>0，否则0
Cvm_in = clip100(
    28×ha + 26×hq + 24×L
  + 10×Td + 12×S + Bstreak - 12×Tu
)
```

连续 12 个低负载预测点即可拿满 8 分，按点数而非小时计算。代码注释提到“全部预测点低于保护值”，但实际实现是上面的**最长连续低负载点数**公式，判定低负载用 `consecutive_low_threshold`，默认 0.2。

### 4.5 K8S 扩容

```text
Ck8s_out = clip100(
    42×min(1,p) + 20×min(1,k) + 14×min(1,a)
  + 16×clip(H) + 8×Tu - J
)
```

与 VM 相比，没有超饱和奖励。

### 4.6 K8S 缩容

```text
Ck8s_in = clip100(
    34×ha + 30×hq + 18×L
  + 10×Td + 8×S - 12×Tu
)
```

与 VM 相比，空闲度权重更高，持续性和稳定性权重不同，没有连续点数奖励。两个缩容公式中的 L 直接使用统计得到的 0～1 比例。

## 5. 资源级置信度汇总

### 5.1 同方向证据选取

```text
存在扩容指标：Cbase = max(扩容指标置信度)
不存在扩容指标：Cbase = min(缩容指标置信度)
没有有效动作指标：Cbase = 0
```

保持动作的指标不参与汇总。单指标函数对非扩缩容动作的默认返回值 50 不会成为资源级默认置信度。

K8S 多容器先按同一个 CPU/内存指标合并：存在扩容容器就选扩容方向及其最大分，否则取缩容方向及其最小分；再按上述规则汇总 CPU/内存。容器分数缺失或非有限时按 0 参与合并。单个容器扩容和另一个容器缩容也构成混合信号。

### 5.2 K8S 质量调整

在容器原始证据合并后，检查资源及相关容器的 CPU/内存 Request/Limit 质量，每类调整只应用一次：

| 条件 | 调整 |
| --- | --- |
| 存在 poor | -18 |
| 存在 fair | -8 |
| 资源或容器存在 blocker（指标缺少有效证据） | -12 |
| 资源或容器存在 baseline_missing（规格基线缺失） | -6 |

poor 和 fair 是两个独立条件，可以同时扣分，例如不同指标分别为 poor/fair 时共扣 26 分。good/unknown 本身没有加减分；数据是否可用还受 blocker 等检查约束。

VM 的资源置信度汇总没有这组 K8S 专属质量扣分；数据质量仍由独立执行门控检查。

### 5.3 混合信号、短历史和最终范围

```text
Dquality = K8S上述质量调整之和；VM取0
Dmixed = -8（有混合信号），否则0
cap = 71（混合信号或非hold且历史不足），否则100
C = round(max(0,min(cap,Cbase+Dquality+Dmixed)),2)
```

VM 实现中先汇总并处理混合信号，之后再做短历史封顶；K8S 将短历史 cap 一起传入汇总。VM 先将单指标分保留两位小数；K8S 多容器汇总使用容器输出中保留两位小数的指标分，最终结果也保留两位小数。

短历史默认以 `history_coverage.span_hours<120` 判断；提供非零 `threshold_hours` 时以其为准。缺失或无法解析 span_hours 在有效覆盖对象中按 0 处理；hold 不触发短历史封顶。VM 调用方完全不提供覆盖对象时不进行这项封顶；K8S 读取不到覆盖对象时默认空对象，因此非 hold 会按不足处理。

| 最终置信度 C | 等级 |
| --- | --- |
| 0≤C<45 | low / 低 |
| 45≤C<72 | medium / 中 |
| 72≤C≤100 | high / 高 |

封顶修正也会写入 `confidence_breakdown.components`，例如 `90-8=82` 再封顶 71，会附加 `-11` 的修正项。没有多指标数量加分、最高分与平均分加权、执行就绪加分。

## 6. 完整算例

以下为人工构造的计算示例，使用 balanced 默认阈值。动作、目标规格视为已经由建议算法给出，不用评分反推动作。没有混合、质量扣分，历史覆盖充足，且仅示例指标参与评分，除非另有说明。

### 6.1 持续 98% 负载：VM CPU 扩容

12 个预测点均为 0.98，因此：

```text
A=Q=K=V=0.98，G=0，H=1，L=0，Nlow=0，s=0，d=0
To=0.8，Tp=0.85，Tu=0，J=0
```

紧急度逐步计算：

```text
P = (0.98-0.8)/(1-0.8) = 0.9
E = (0.98-0.85)/(1-0.85) = 0.8666667
折减峰值压力 = 0.75×0.8666667 = 0.65
B = 40（触阈）
U = 40 + 60×max(0.9,0.65) = 94分，等级“紧急”
```

置信度逐步计算：

```text
p=0.9，k=0.8666667，a=0.9
P95项 = 42×0.9 = 37.8
峰值项 = 20×0.8666667 = 17.3333333
均值项 = 14×0.9 = 12.6
持续项 = 16×1 = 16
趋势项、超饱和奖励、尖峰惩罚均为0
C = 37.8+17.3333333+12.6+16 = 83.7333333
最终 C=83.73分，等级“高”
```

K8S 扩容在相同统计和阈值下也得到 83.73 分，因为本例没有超饱和奖励差异。

### 6.2 持续 4% 负载：VM CPU 缩容

12 个预测点均为 0.04，当前 CPU 为 4C，目标为 2C，其他维度不贡献更大的回收比例：

```text
A=Q=K=V=0.04，G=0，H=0，L=1，Nlow=12，s=d=0
Ta=0.2，Tq=0.35，Tu=Td=0，S=1
ha = (0.2-0.04)/0.2 = 0.8
hq = (0.35-0.04)/0.35 = 0.8857143
R = 1-2/4 = 0.5
```

紧急度：

```text
F = min(0.8,0.8857143) = 0.8
U = 60×0.8 + 25×1 + 15×0.5
  = 48+25+7.5 = 80.5分，节省机会“高”
```

VM 置信度：

```text
均值空闲项 = 28×0.8 = 22.4
P95空闲项 = 26×0.8857143 = 23.0285714
持续项 = 24×1 = 24
下降趋势项 = 0
稳定项 = 12×1 = 12
连续奖励 = 8×min(1,12/12) = 8
上涨惩罚 = 0
C = 22.4+23.0285714+24+12+8 = 89.4285714
最终 C=89.43分，等级“高”
```

K8S Request 具有同样统计时，单指标缩容置信度为：

```text
C = 34×0.8 + 30×0.8857143 + 18×1 + 10×0 + 8×1 - 12×0
  = 27.2+26.5714286+18+8 = 79.7714286
最终单指标分=79.77
```

这只是 K8S 单项证据分，资源最终分还要经过同方向最弱项选择和质量调整。

### 6.3 混合信号及封顶

```text
CPU扩容证据=90，内存缩容证据=95
扩容优先：Cbase=90（不使用内存95来支持扩容）
混合扣分：90-8=82
混合封顶：min(82,71)=71
最终置信度=71，中等；封顶修正项=-11
```

若没有混合，但预测历史仅 3 天且仍建议扩容：`min(90,71)=71`，短历史修正项为 `-19`。

### 6.4 K8S 多类质量问题

已选出的扩容原始证据为 90；不同指标同时出现 poor/fair，存在 blocker 和缺基线，且没有混合：

```text
C = max(0,90-18-8-12-6) = 46分，中等
```

若再有混合信号：`max(0,min(71,46-8))=38`，低置信度。即使紧急度很高，也不能靠紧急度抵消这些扣分。

## 7. 复核顺序与代码位置

复核某资源时，先看动作及 `policy_tier`，再取预测 `stats`（K8S 同时看容器统计），按本文计算单指标分和资源汇总。置信度是预测时保存的结果；若配置后来变化，应重新预测再比较。紧急度在 API 读取时使用当前配置计算，可能与旧置信度所用配置时点不同。

| 实现 | 位置 |
| --- | --- |
| 统计均值、P95、峰谷差 | [utils.py](../resource_predict/utils.py)，`compute_metric_stats` |
| 默认配置 | [internal_settings.py](../resource_predict/internal_settings.py)，`DecisionConfig` |
