# 预测反馈性能优化

用户已授权进行生产规模性能优化。按 brainstorming、ponytail 和 writing-plans 流程先测量、再优化共享热路径；保留当前未提交功能。

基线负载：10000 资源、每资源 1 容器、每容器 4 指标、7 个每日批次、每曲线 24 点，共 6720000 点，SQLite 约 598 MB。实测补评 6.41 秒，汇总 23.40 秒，40000 条指标校准 39.26 秒。

1. 新增 benchmarks/forecast_feedback_benchmark.py，提供可重复、隔离生产数据的磁盘数据库负载。默认覆盖万资源及 7 天历史；结果只代表反馈路径，不包含模型拟合或 Prometheus。
2. 校准使用单次有序游标，按提前量分组去重和限量，每组不超过 500；保留时点、规格、版本、配置、原样本摘要及分位公式。
3. 报告先按曲线/提前量计算合计，再汇总模型分组，验证结果保持按点加权。raw 提交仅提交评分和保留期清理，正式报告在预测结束或显式 CLI 重试时生成，避免一轮重复全量汇总。
4. 记录阶段耗时、进程峰值内存、数据库大小；验证无生产副作用。增加结果一致性与延迟报告回归测试，运行全套静态检查和 pytest。
5. 更新 development 文档和测量记录，清理缓存。生产长周期、不同模型与更多容器场景的容量界限明确记录，不将本机合成负载冒充生产 SLA。
