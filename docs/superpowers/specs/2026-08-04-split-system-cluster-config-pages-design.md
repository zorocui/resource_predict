# 系统配置与集群配置页面拆分设计

## 目标

将当前混合的“系统配置”工作区拆成两个一级导航页面，使运行参数和基础设施接入分别管理，同时保持现有配置存储、校验和运行时生效机制不变。

## 页面边界

### 系统配置

系统配置页面只包含：

- 数据采集：定时拉取开关、周期、历史窗口、步长、CPU rate 窗口和请求超时；
- 预测配置：VM/K8S 预测窗口、候选模型和 Ensemble 开关；
- 扩缩容策略：策略等级、阈值、确认轮次、冷却时间和命名空间策略。

页面使用独立的“保存系统配置”按钮和状态消息，不展示集群凭据或 Prometheus 接入操作。

### 集群配置

集群配置页面只包含：

- VM/K8S 调配控制节点；
- K8S Prometheus 监控接入；
- 新增、移除、诊断接入和立即拉取操作。

页面使用独立的“保存集群配置”按钮和状态消息。K8S 自动拉取摘要保留在此页面，因为它直接解释 Prometheus 接入的运行状态；调度参数本身仍在系统配置页面编辑。

## 数据与保存流程

继续使用 `GET/PUT /api/system-config` 和现有三个存储文件，不新增后端端点。

前端读取配置后缓存完整响应，并同时渲染两个页面。保存系统配置时提交页面编辑后的 `runtime`，同时带上缓存中的集群配置；保存集群配置时提交页面编辑后的集群配置，同时带上缓存中的 `runtime`。服务端仍执行一次完整校验和原子保存，任一页面保存都不会清空另一页面的数据。

保存成功后更新完整缓存并重新渲染两个页面。保存失败时只在当前页面显示错误并保留输入值。诊断和拉取消息只出现在集群配置页面。

## 导航与响应式布局

一级导航增加“集群配置”，原 `configs` 视图改为 `system-config`，新增 `cluster-config` 视图。两个页面沿用现有配置卡片和窄屏响应式样式，不引入新的视觉体系。

## 验证

- 静态模板测试确认存在两个导航入口、两个视图和两个独立保存按钮；
- JavaScript 逻辑检查确认进入任一配置页面都会加载统一配置；
- 后端系统配置回归测试确保完整保存行为不变；
- 浏览器验证桌面和窄屏下页面切换、字段边界和保存状态。
