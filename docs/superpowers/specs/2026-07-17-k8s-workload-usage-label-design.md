# K8S 风险队列 Workload 聚合使用率展示设计

## 背景

风险队列当前展示 K8S CPU、内存历史观测 P95。数值来自 Workload 级聚合序列，但标签只在末尾显示 `Workload`，没有说明聚合公式和参与计算的容器范围。详情弹窗又会展示选中 Container 的统计，导致多容器资源看起来像同一使用率前后不一致。

Workload 使用率不是各容器使用率的算术平均。每个时间点的计算口径是：

```text
Workload 使用率 = 参与计算容器的使用量总和 ÷ 对应 Request/Limit 总和
风险队列显示值 = Workload 历史观测使用率序列的 P95
```

该结果等价于按 Request/Limit 规格加权的容器使用率，而不是容器百分比的简单平均。

## 目标

- 风险队列明确显示其数值是 `Workload 聚合 P95`。
- 用户可以从提示中看到聚合公式、统计窗口和参与容器数量。
- 详情弹窗继续展示当前选中 Container 的统计，并保留明确的 Container 名称和范围标签。
- 百分比模式与缺少 Request/Limit 时的绝对值模式使用准确、不同的文案。
- 不在风险队列展开各容器明细，不增加列表接口或图表请求。

## 方案选择

采用“明确标签 + 口径提示”方案：风险队列内保持一个 CPU 和一个内存指标胶囊，在胶囊中直接标明 `Workload 聚合 P95`，并通过信息提示说明计算范围。相比只改一个词，该方案能够解释数值；相比展开所有容器，它不会增加高密度列表的体积和网络开销。

## 前端展示

百分比模式示例：

```text
CPU Limit · Workload 聚合 P95 66.7%  i
内存 Request · Workload 聚合 P95 42.3%  i
```

提示内容：

```text
统计口径：参与容器使用量总和 ÷ Limit 总和，不是容器使用率的算术平均。
参与计算：2/3 个容器。
统计范围：完整历史观测窗口的 P95。
```

绝对值模式示例：

```text
CPU 使用量 · Workload 汇总 P95 1.20 C  i
内存使用量 · Workload 汇总 P95 800 MiB  i
```

绝对值模式的提示不出现“使用率”或除法公式，改为：

```text
统计口径：所有观测容器使用量之和。
参与计算：3 个容器。
统计范围：完整历史观测窗口的 P95。
```

详情弹窗保持容器级展示，例如 `CPU Limit · app` 和 `P95 · Container`。风险队列与弹窗不要求数值相等，但两处必须分别明确标注 Workload 聚合与 Container 范围。

## 参与容器计数

前端使用摘要项已有的 `spec.containers` 和 `spec.containers_observed` 计算，不修改 API：

- 总容器数：两个字段中有效容器名称的并集数量。
- `cpu_limit`：规格中存在正数 `cpu_limit_cores` 的容器数。
- `cpu_request`：规格中存在正数 `cpu_request_cores` 的容器数。
- `memory_limit`：规格中存在正数 `memory_limit_gb` 的容器数。
- `memory_request`：规格中存在正数 `memory_request_gb` 的容器数。
- 百分比模式显示 `参与数/总数`；绝对值模式显示全部观测容器数。

如果容器元数据缺失或数量为零，提示显示“参与容器：范围信息缺失”，不猜测数量。若参与数等于总数，也仍显示 `N/N 个容器`，保持口径稳定。

## 组件边界与数据流

在 `static/js/resource-list.js` 增加纯展示辅助函数，负责：

1. 根据指标 key 映射容器规格字段。
2. 计算总容器数和参与容器数。
3. 根据 `resolveDisplayUnit()` 生成 `Workload 聚合 P95` 或 `Workload 汇总 P95` 标签。
4. 生成对应提示文本。

`k8sMetricSummary()` 继续负责选择扩容使用 Limit、缩容使用 Request 的代表指标，只把选出的指标、单位和统计值交给上述辅助函数。现有 `observed_stats`、建议动作、排序和详情弹窗的数据流不变。

## 性能与兼容性

- 所有信息从当前页摘要项计算，不读取详情分片或容器图表。
- 每行只遍历该 Workload 的容器规格；列表默认分页且 API 上限为 200，适合生产规模。
- VM 风险队列展示完全不变。
- 旧 K8S 摘要缺少 `spec.containers` 时仍展示 Workload 标签和 P95，只将提示中的参与范围标记为缺失。
- 不改变输出 schema、预测产物或后端缓存。

## 测试与验收

实现后验证以下场景：

1. 多容器百分比模式显示 `Workload 聚合 P95`，提示包含公式和 `参与数/总数`。
2. 单容器百分比模式显示 `1/1 个容器`。
3. 部分容器缺少对应 Request/Limit 时，参与数小于总数。
4. 绝对值模式显示 `Workload 汇总 P95`，提示不包含使用率除法公式。
5. 容器元数据缺失时正常渲染并提示范围信息缺失。
6. VM 风险队列文案不变。
7. 打开多容器详情后，弹窗仍显示选中容器名称及 `P95 · Container`。

使用本地产物进行浏览器验证，并按项目要求运行 Python 完整回归检查。验收标准是用户无需比较数值即可辨认：队列是 Workload 聚合统计，弹窗是选中 Container 统计。
