# K8S Prometheus 缺口容错与预测区域边界设计

## 背景

K8S Workload 指标由 Prometheus 定时拉取并增量合并。生产环境中，长时间范围查询可能因超时、限流、连接中断或服务端错误失败。不同轮次成功返回的 Workload 集合也可能不同，导致原始时间序列出现大缺口。

当前链路会放大这些问题：

- Prometheus HTTP 请求没有重试，长时间 `query_range` 也没有分片；一次瞬时故障即可令整个集群本轮失败。
- 稀疏序列的实际时间差可能覆盖数小时或数天，但预测窗口会优先使用该中位间隔，覆盖掉 K8S 已配置的采样步长。
- 启用 `reuse_backtest_model_for_future` 时，未来预测索引从训练段外推。若测试段时间不规则，未来索引可能落入真实测试区间。
- 前端黄色 `markArea` 只检查未来预测点自身，没有把测试数据末点作为硬边界。
- 大缺口两侧的历史线或测试线会被直接连接，形成并不存在的连续趋势。

因此，黄色区域可能覆盖测试数据；预测曲线的时间语义也可能错误。用户确认的显示口径是：黄色区域表示“测试数据之后的预测”，与当前系统时间无关。

## 目标

- 提高 Prometheus 拉取面对瞬时故障和大响应的成功率。
- 部分集群或部分 Workload 拉取失败时保留已有原始数据与预测产物。
- 使用配置的 K8S `step_seconds` 作为预测时间轴的权威采样间隔。
- 所有未来预测点严格晚于最后一个测试数据点。
- 黄色区域从测试数据末点开始，到最后一个有效未来预测点结束，绝不覆盖测试区间。
- 大数据缺口不进行无限插值，也不在图表中跨缺口连线。
- 数据不足以可靠预测时，保留旧预测并明确记录质量问题。

## 非目标

- 不改变预测模型的数值算法、模型选择规则或阈值决策规则。
- 不把过期预测平移到当前时间；预测边界只由测试末点和规范采样间隔决定。
- 不因单轮 Prometheus 缺失就推断 Workload 已删除。资源删除需要独立、明确的生命周期机制。
- 不用全量二次拟合替代回测模型复用；生产规模下应保留单次拟合优化。

## 方案概览

采用分层防护：

1. 采集层对时间范围查询分片，并对瞬时错误执行有限重试。
2. 合并层只更新成功返回的资源，未返回资源保持原样。
3. 序列层只填充短缺口；大缺口保留为不连续边界。
4. 预测层以配置采样间隔重建未来时间索引，并以测试末点为锚点。
5. 展示层再次裁剪未来点，以测试末点作为黄色区域的硬边界。

后端负责生成语义正确的产物，前端防护用于兼容旧产物或异常产物，不能替代后端修正。

## Prometheus 查询可靠性

### 时间范围分片

`PrometheusClient.query_range()` 将完整时间范围拆分为多个相邻片段。默认分片时长为 24 小时；不足一个分片的增量窗口仍只发起一次请求。片段边界允许重叠一个采样点，合并时按完整标签集和时间戳去重，后返回的数据覆盖同时间戳的先返回数据。

分片降低单次响应大小和 Prometheus 查询峰值内存，但不会改变最终查询时间范围、查询表达式或配置的 `rate_window`。

### 有限重试

每个 HTTP 请求独立重试，默认最多 3 次尝试，采用指数退避。以下情况可重试：

- 网络连接错误、连接重置和读取超时；
- HTTP 429；
- HTTP 5xx。

除 429 外的 HTTP 4xx、响应 JSON 无效、Prometheus 明确返回查询语义错误时立即失败。日志记录集群、请求类型、片段范围、尝试次数和最终错误，但不输出认证信息。

同一 `query_range` 的任一片段在重试后仍失败，则整条查询失败。本轮不提交该查询的部分片段，避免把不完整时间范围误认为完整采集。

### 集群结果

一个集群所需的 CPU、内存和元数据查询全部成功并能聚合出 Workload 时，该集群记为成功。失败集群记录错误、耗时和尝试信息；其他成功集群仍继续合并，整体状态为 `partial_success`。

## 增量合并与资源保留

K8S 拉取继续使用 upsert 语义：

- 本轮成功返回的 Workload 按资源 ID 合并新时间点、容器指标和当前规格。
- 同一时间戳去重并保留本轮新值。
- 本轮未返回的既有 Workload 不删除、不清空、不改写。
- 失败集群的所有既有 Workload 保持原始分片与预测产物不变。
- 只对本轮数据发生有效变化且满足质量要求的资源重算预测；部分预测合并继续保留未重算资源。

这些行为增加回归测试以防止未来把“本轮缺失”误解释为“资源删除”。

## 缺口处理与数据质量

### 权威采样间隔

K8S scope 的 raw 元数据继续保存 `step_seconds` 对应频率。解析测试时长和未来时长时，K8S 优先使用该配置频率，不让稀疏观测的中位时间差覆盖它。VM 保持现有的实际频率推断逻辑。

预测上下文携带规范 `sample_interval_seconds`，同一轮 K8S 预测的窗口换算和未来索引使用同一口径。

### 短缺口与大缺口

重采样后只对不超过配置阈值的连续缺失点做时间插值。默认阈值为 3 个采样间隔，即 5 分钟采样时最多补 15 分钟。更大的缺口不跨段插值。

预测选择末尾最近的连续有效数据段。该数据段必须满足回测窗口和模型最小数据量要求；不满足时跳过该资源或指标的本轮预测，并通过现有部分预测合并保留旧产物。数据质量记录至少包含：

- 实际有效点数和期望点数；
- 缺失比例；
- 最大缺口秒数；
- 最近连续段点数和覆盖时长；
- 数据截止时间；
- 是否因质量不足跳过预测。

图表构造时在超过缺口阈值的位置插入断点，历史线和测试线均不跨大缺口连接。

## 预测时间轴

### 规范未来索引

`fit_one_metric()` 保留单次拟合优化。模型产生未来数值后，不直接信任从不规则训练索引外推得到的时间戳，而是为所有模型统一重建未来索引：

```text
future[0] = last_test_timestamp + sample_interval
future[i] = future[0] + i * sample_interval
```

规范索引长度等于 `future_steps`。回测预测仍使用真实 `y_test.index`，指标评分逻辑不变。所有模型共享同一未来索引，集成预测也使用该索引。

如果测试末点或规范采样间隔无效，则该指标预测失败，不生成含糊的未来时间轴。

### 产物元数据

图表预测产物补充或确保可推导以下字段：

- 最后测试时间 `test_end_ms`；
- 规范采样间隔 `sample_interval_seconds`；
- 未来预测时间 `x_pred_ms`；
- 数据截止时间和质量摘要。

`x_pred_ms` 的每个值必须严格大于 `test_end_ms`，且相邻点间隔等于规范采样间隔。

## 前端边界与图表断点

前端构建未来预测数据时先计算最后一个有效测试时间。所有时间戳小于或等于该时间的未来点均被丢弃，防止旧产物或异常产物污染图表。

黄色区域使用以下边界：

```text
start = 最后一个有效测试时间
end   = 所有可见模型中最后一个有效未来预测时间
```

仅当 `start < end` 且至少存在一个严格晚于 `start` 的有效未来点时创建 `markArea`。测试点参与确定起点，但测试预测值不参与确定终点。当前时间不参与边界计算。

未来预测曲线使用与黄色区域相同的过滤规则，因此不会出现色带正确但曲线仍落入测试区间的分叉行为。

历史线和测试线根据规范采样间隔识别大缺口，在缺口两侧插入空值断点并保持 ECharts `connectNulls=false`。

## 配置

在 K8S Prometheus 运行配置中增加以下字段，并在配置读写、页面表单和文档中保持一致：

| 字段 | 默认值 | 含义 |
|---|---:|---|
| `range_query_chunk_hours` | `24` | `query_range` 单个分片的最大时长 |
| `request_max_attempts` | `3` | 每个 Prometheus HTTP 请求的最大尝试次数，包含首次请求 |
| `retry_backoff_seconds` | `1` | 首次重试等待时间，后续指数增长 |
| `max_interpolation_gap_steps` | `3` | 允许自动插值的最大连续缺失采样点数 |

所有字段必须为正数；配置缺失时采用默认值，以兼容现有部署文件。

## 错误处理

- 单个请求最终失败：终止当前集群聚合，记录失败，不提交该集群本轮部分数据。
- 部分集群失败：提交成功集群，整体为 `partial_success`。
- 所有集群失败：不执行 upsert，不覆盖任何 raw 或预测产物，任务为 `failed`。
- Workload 最新连续段不足：保留 raw 合并结果，但跳过该 Workload 或指标的预测重算并保留旧预测。
- 规范未来索引无法建立：该指标失败，不回退到可能覆盖测试区间的模型索引。
- 前端收到旧或异常产物：裁剪落入测试区间的未来点；无剩余未来点时不显示预测曲线未来段和黄色区域。

## 测试

### Prometheus 客户端

- 超时、连接错误、HTTP 429 和 HTTP 5xx 按上限重试并执行退避。
- 普通 HTTP 4xx 和查询语义错误不重试。
- range 查询按配置分片，片段覆盖完整窗口。
- 分片结果按标签和时间戳合并、排序、去重。
- 某分片最终失败时不返回其他片段的部分结果。

### 合并与部分成功

- 一个集群失败、一个集群成功时只合并成功集群并记录 `partial_success`。
- 本轮 Workload 子集变化时，未返回的既有 Workload raw 分片和预测产物保持存在。
- 所有集群失败时 raw 索引和预测清单不变。

### 缺口与预测

- K8S 配置为 5 分钟、观测中存在数小时或数天缺口时，测试和未来步数仍按 5 分钟换算。
- 不超过阈值的短缺口可插值，超过阈值的大缺口不插值。
- 最近连续段不足时跳过重算并保留旧预测。
- 开启回测模型复用时，未来首点等于测试末点加 5 分钟。
- 所有未来点严格晚于测试末点，多模型索引一致。

### 前端

- 异常未来点落入测试区间时被过滤。
- 黄色区域从最后测试时间开始，到最后有效未来点结束。
- 只有一个有效未来点时，只要它晚于测试末点即可形成从测试末点到该点的非零区域。
- 无有效未来点时不创建黄色区域。
- 历史线和测试线在大缺口处断开。

### 回归检查

实现完成后运行 JavaScript 图表测试，以及项目规定的 Python 全量检查：`compileall`、`pyflakes`、`vulture --min-confidence 80` 和 `pytest -q`。命令使用项目本地 Windows 虚拟环境。检查产生的项目 `__pycache__` 在完成后清理，`.venv` 内缓存不处理。

## 风险与控制

- 分片会增加请求数量。默认 24 小时在可靠性和请求开销间折中，增量窗口短于该值时不增加请求数。
- 重试会延长失败任务耗时。尝试次数和退避可配置，并继续受单请求超时控制。
- 不跨大缺口插值会减少可用于预测的数据。系统宁可保留旧预测并标记质量问题，也不基于虚假连续数据生成新建议。
- 前端裁剪可能隐藏旧产物中的全部未来预测。这是正确的防御行为；后端重新预测后应恢复规范时间轴。
- 资源不能依据一次缺失自动删除，避免采集波动造成误删；真正删除资源需要另行设计带确认期的生命周期策略。
