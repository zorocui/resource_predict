# K8S Prometheus 默认采集参数调整设计

## 目标

将 K8S Prometheus 默认采样步长从 5 分钟调整为 10 分钟，将 CPU `rate()` 默认窗口从 5 分钟调整为 15 分钟。修改后，默认每 10 分钟产生一个查询结果点，每个 CPU 结果点使用此前 15 分钟的样本计算平均使用核数。

## 配置变更

| 配置项 | 当前默认值 | 新默认值 |
| --- | --- | --- |
| `step_seconds` | `300` | `600` |
| `rate_window` | `5m` | `15m` |

现有的显式集群配置继续优先于全局默认值，配置解析规则和 PromQL 拼接方式保持不变。

## 修改范围

- 更新 Python 运行配置、内部设置和 Prometheus provider 中的生效默认值与回退值。
- 更新前端配置表单中的空值回退和输入提示。
- 更新已提交的 `deploy/runtime_config.json`，使当前部署使用新参数。
- 更新配置文档中的默认值、示例和采样点数换算示例。
- 更新断言默认配置的测试；保留显式传入 `300` 或 `5m`、用于验证其他行为的测试参数。
- 不修改既有 `docs/superpowers/specs/` 和 `docs/superpowers/plans/`；这些文件保留其设计时的历史事实。

## 数据与兼容性

此次调整不改变输出 schema、Prometheus 指标名称、Workload 聚合逻辑或使用率计算公式。`step_seconds=600` 会降低默认时间序列分辨率及查询/预测负载；`rate_window=15m` 可在 Prometheus 每 5 分钟抓取一次时为 `rate()` 提供更稳定的样本数量。已有明确配置其他值的部署不受默认值变化影响。

## 验证

- 运行运行配置默认值测试。
- 运行 K8S Prometheus provider 相关测试，确认可配置 `rate_window` 仍被用于 CPU 查询。
- 搜索当前生效代码、前端、部署配置与正式文档，确认不再残留 `300` / `5m` 的旧默认回退。
- 对修改过的 Python 文件执行编译检查，并清理项目 `.venv` 外生成的 `__pycache__`。
