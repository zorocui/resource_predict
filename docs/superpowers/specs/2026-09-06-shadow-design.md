# 校准上界建议的影子对照

用户要求继续已推荐的下一步：同时保存现有建议和基于校准上界的对照建议，用之后到达的真实观测核验。前两轮未提交的回填和校准代码是本轮基础，全部保留。

## 方案与边界

- 复用现有 VM/K8S 建议算法，仅将入选预测替换为完整校准上界，以隔离该输入的影响。不改原建议，不创建执行任务；影子对象 executable=false，不携带执行门控。
- 新生成资源的全部指标、K8S 全部已知容器必须有完整且同口径的上界。局部重算、部分校准、缺容器均标记 unavailable，不将旧预测拼成新对照。
- 保存跨轮次确认之前的 baseline 和 candidate（action、target_spec、policy_tier）、原规格与预测时间窗口。后续规格变化不将旧对照冒充当前可比方案。
- 资源量按 VM 规格或 K8S 容器规格乘目标副本数计算；CPU 和 GiB 分开，request 与 limit 分开，不产生 Workload 汇总当前规格字段。
- 对已获真实评分的同一预测点，比较 actual 与两种建议规格相对原规格的比例。K8S 仅对同副本数、同成员且有 request/limit 比值口径的容器评分；副本变化/缺规格/绝对值口径记录跳过。request 超出是预留预算超出，不是业务容量故障。
- 新增 SQLite shadow_runs 和 shadow_budgets，和留档同批次事务导入、唯一约束、级联保留期清理。历史无影子对象不补造结果。配对比较使用相同真实观测集合，不通过事后重训替换建议。
- 报告包含建议资源量均值及差值、同批真实点的超出率/超出归一化幅度、相邻同规格有效建议的变更次数及比例。未匹配数据不是零风险；变更率是建议变更而非真实执行振荡。

这是基于保持实际需求不变的离线反事实对照，不能证明执行新规格后的性能、SLA、业务风险或费用收益。对照继续使用现有算法余量，因此不预设校准后资源一定减少。

## 验收

原正式建议不变、只替换输入、缺样本不配对、容器 request/limit 分开、分数容量保留、副本变化不伪评分、留档后评分幂等、迟到数据沿用既有回填机制、保留期清理、变更频率、局部重算排除。运行全套静态检查与回归并清理缓存。
