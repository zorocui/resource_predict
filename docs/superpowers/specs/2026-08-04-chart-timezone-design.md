# 曲线图北京时间显示修复设计

## 问题

Prometheus 返回 Unix epoch 时间戳，K8S provider 以 UTC 正确解析并在 API 中继续使用毫秒级 epoch。
前端曲线格式化函数却显式使用 `UTC`，导致部署在 UTC+8 的国内环境中，横轴和 tooltip
显示时间与北京时间相差 8 小时。

## 方案

将曲线图统一展示时区从 `UTC` 改为 IANA 时区 `Asia/Shanghai`。不修改时间戳数值、
Prometheus 查询、后端序列、预测窗口或图表数据点位置，只改变横轴标签和 tooltip 的显示文本。

相比使用浏览器本地时区，固定 `Asia/Shanghai` 能保证不同终端访问同一内部系统时看到一致的业务时间；
相比在后端给 epoch 增加 8 小时，该方案不会破坏 Unix 时间戳语义，也不会造成二次偏移。

## 验证

增加 JavaScript 单元测试，使用一个已知 UTC epoch，验证短时间范围横轴标签按北京时间输出。
保留现有图表数据、预测区间和零值处理测试，并运行项目完整回归检查。
