# 预测准确性统计与佐证

页面入口为顶部“预测准确性”，与扩缩容建议置信度、调配成效分别统计。主要指标是明确容差下的达标率，不能用置信度分数或 `100%-MAPE` 替代。校准与验证功能已移除，不影响此处的独立历史测试统计。

## 当前默认：轻量历史测试准确率

模型选择使用外层训练段内的时间验证集：利用率优先选择验证容差达标率最高的模型，相同时按 `selection_rmse` 最小选择；绝对核数/GiB 仍按 RMSE。默认最多3折，将各折有效点合并统计，并记录 `validation_accuracy`、`validation_hit_points`、`validation_valid_points`、`validation_worst_accuracy`，各折结果位于诊断的 `validation_fold_accuracies`。这些字段同时进入误差报告，不能与页面的独立测试准确率混用。页面、默认预测曲线及建议使用实际选中的模型；新规则需重新预测后生效，不保证某一测试窗口达到指定准确率。

打开页面直接读取 `forecast_accuracy_summary.json`，没有必填条件或评估来源切换。每次预测对本轮新生成资源的实际选用模型计算独立历史测试汇总，自动覆盖对应 scope 的上一份汇总；增量预测仅代表本轮重算范围。K8S 有容器预测时优先统计容器，避免与 Workload 汇总重复计数。

详情页“重新拉取预测”使用局部更新：仅替换目标资源的汇总行，保留其他资源结果；`mixed_prediction_runs=true` 表示数据来自多个预测批次，页面会明确提示。局部更新行记录 `generated_at_ms`，旧全量生成时间保留在 `full_run_generated_at_ms`，不能把最近局部更新时间当作所有资源的预测时间。

准确率 = 绝对误差不超过 `max(5 个百分点, 实际值绝对值 × 5%)` 的有效点数 / 有效测试点数。内部利用率以比值保存（4000%为40），对应判断为 `abs(predicted-actual) <= max(0.05, abs(actual)*0.05)`，边界计为达标。例如实际4000%时允许预测3800%～4200%；实际50%或0%时仍允许相差5个百分点。平均绝对误差MAE仍按百分点计算，不随容差规则改变。无效值、非独立测试不计入分母；绝对核数/GiB等非比例指标仅报告原单位MAE，不混入准确率。无有效点显示“—”，不显示0%。测试仍基于预处理历史数据，不等于未来兑现结果。

新汇总 `forecast_accuracy_summary.json` 的 `version=2`。旧版 `version=1` 只保存固定5个百分点口径的达标点数，无法换算；API通过 `needs_regeneration` 返回待重新预测的scope，并从当前计数中排除这些旧汇总，页面及CSV均提示。新旧口径不会合并计算。

K8S 按各容器、各指标的实际单位分别判断 Request/Limit 基线：缺少对应基线时，虽然指标名仍含 `request` 或 `limit`，数据已回退为核数/GiB，不参与准确率、有效点、达标点及测试资源数统计；仅配置 Request 或仅配置 Limit 时，只统计有基线的利用率指标。指标单位缺失时也不推定为利用率。修复前生成的汇总需重新预测后更新。

页面显示资源数、有效点、达标点、测试时间、各scope更新时间及前100条汇总；CSV包含全部汇总行和统计口径，可截图或打印保存PDF作为材料。只保存每条曲线的计数和误差汇总，不保存逐点数组。

升级后需要完成一次新预测生成新汇总；单纯拉取数据不会生成历史测试准确率。旧误差报告没有达标点计数，不伪造回填。逐点留档生成、SQLite导入及手动补导入入口已删除，没有重新开启这些流程的配置开关。服务器旧数据文件不会自动删除，旧高级只读API不属于当前页面依赖。

接口：`GET /api/forecast-accuracy/summary`，返回最新各scope汇总、合并计数与逐曲线汇总。读取损坏文件返回503，不能当作无数据。
