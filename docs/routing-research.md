# 成本感知路由：第一阶段实验协议

本阶段检验追加 Prophet 的收益是否存在异质性，并建立后续学习用的成对记录。
不修改在线预测、模型开关或执行门控。现有规则路由不是本实验的筛选条件。

## 实施计划与验收

1. 新增独立 `benchmarks/routing_pilot.py`，复用项目模型调用，支持合成数据和只读 raw 快照。
2. 验证时间隔离、失败记录与缺失处理；运行首轮合成场景与本地快照试验。
3. 留存逐模型误差、计时、输入摘要与配置；解释结论边界。
4. 在真实来源确认、跨业务代表性及重复测量具备后，才能判断是否进入第二阶段。

## 固定协议

- 基础候选：Seasonal Naive、Rolling Mean；增强候选：基础候选加 Prophet；不启用集成。
- 每个起点使用历史末尾一个 horizon 作为内部验证，验证前历史生成路由特征。
- 按验证 RMSE 选型，然后在起点前完整历史上重新拟合，在后续 horizon 独立评分。
- 多起点间隔 horizon；测试窗口不重叠，但同资源各起点仍相关，不作独立样本显著性推断。
- 全候选测试评分仅用于离线诊断，绝不参与选型。失败保留，不用测试结果挑选替代模型。
- 串行执行，每起点轮换模型顺序。工作流成本估算为候选验证耗时之和加选中模型重拟合耗时。
- 两流程复用测得阶段成本，避免重复拟合；成本是估算的单工作流墙钟时间，不是独立 A/B 实测、CPU 秒或批次吞吐。
- Prophet 后端可能启动子进程，本实验不使用 Python process_time 冒充总 CPU 成本；没有硬超时隔离。
- 原始时间必须有序、唯一、等间隔、无缺失；不跨缺口插值。不合格窗口明确跳过。
- raw 按随机种子抽样资源，K8S 优先容器序列，避免同时统计 Workload 聚合曲线。
- 默认合成六类场景只用于链路和假设探索；本地 raw 默认标记来源未核验。
- 不跨指标直接平均 RMSE；先报告每条序列的平均配对差异。RMSE 差为正表示增强流程更好。

## 运行

```bash
python -m benchmarks.routing_pilot --output outputs/routing-pilot-synthetic
python -m benchmarks.routing_pilot --raw-dir outputs/vm --limit 12 --horizon 24 --origins 3 --output outputs/routing-pilot-vm
python -m benchmarks.routing_pilot --raw-dir outputs/k8s --limit 12 --horizon 24 --origins 3 --output outputs/routing-pilot-k8s
```

输出目录必须不存在，防止覆盖实验。horizon 单位是采样点，比较不同采样间隔时必须换算成相同实际时长。
Windows 中文路径下使用本地虚拟环境的 `python.exe -X utf8 -m benchmarks.routing_pilot ...`，避免 Prophet 子进程输出按 GBK 解码失败。
`pairs.jsonl` 每完成一个窗口刷新；`report.json` 保存协议、依赖版本、配置、来源、摘要与汇总。
raw 索引运行前后校验；如索引发生变化，该次结果不能视作同一固定快照实验。

## 第一阶段判断边界

首轮试验不能证明可学习性。后续需确认数据来源并扩大至独立业务资源，覆盖多周和多个种子，
按业务与时间留出，以仅训练集拟合的简单收益预测器和常数预测器比较。
采用资源级重采样评估不确定性，重复计时并单独处理冷启动、失败和超时成本。
负收益、跳过和失败必须保留；无足够有效配对时报告证据不足。
不得把本试验当作万级吞吐、生产精度或资源调配收益证明。

### 科研判断

合成场景中 weekly 平均 RMSE 改善约 0.06178，bursts 平均变化约 -0.00340；
本地快照也同时存在正收益、负收益和零收益。这支持“追加模型的收益有差异”这一观察。
它不能证明这些差异能从历史特征稳定预测，也不能证明生产收益。现阶段仅完成实验工具与首轮试验，
第一阶段的最终可行性判断仍需来源确认、多业务长期样本及时间外/业务外验证。

下一批实验应先固定真实数据来源、业务分组和实际预测时长，增加多个非重叠测试时段；
用严格留出的简单线性收益探针对比常数预测，观察是否具备样本外信号。
不要依据本轮测试误差调整路由阈值后再用同一批结果声称泛化收益。
