# 云资源预测成本感知路由——阶段成果总结

整理日期：2026-09-10。用途：阶段汇报、成果说明及答辩。
本次按已有证据收尾，不再追加实验。本文是阶段成果总结，不代表已满足未知的课题合同验收条款。

## 可直接使用的摘要

针对云资源多序列预测中复杂模型计算开销较高、不同序列的预测改善不均匀的问题，
本项目构建了可在内网运行的成对回放、预算路由和汇总分析工具，比较快速预测组合与追加 Prophet 候选的效果。
实验使用内网 30 个 Kubernetes Workload 的 168 条指标序列，形成 7056 条回放记录。
在经过时间划分的开发评价中，研究发现收益尺度处理会明显影响计算分配。
采用还原历史尺度后的收益/成本排序，memory_request 的平均窗口 RMSE 相对快速组合降低约 11.92%，
该方案在同一评价集合上的阶段计算成本估算比全部追加 Prophet 低约 79.2%。
与此同时，CPU 指标仅保持快速基线水平，收益与计算开销存在取舍。
本项目形成了可复现的离线研究流程与候选方法，后续独立时间验证和生产计时尚未完成。

## 成果与量化结果

已交付：内网只读回放工具、脱敏汇总入口、收益及成本路由原型、经验成本校准、
逐时刻预算分析、反馈暂停/恢复研究原型、方法审计和实验文档。
这些工具未自动接入生产调配。研究从多轮开发诊断收敛到收益尺度候选，未声称提出全新基础预测模型。

本次主要评价：26 个精确时刻组、2184 条候选记录，四类指标各 546 个窗口；
首末决策点跨度约 48 小时 10 分钟。不是全部 14 天都作为独立测试。

| 方案 | 阶段耗时估算（秒） | 内存/request 平均窗口 RMSE | 相对快速基线的 RMSE 降幅 |
| --- | ---: | ---: | ---: |
| 快速组合 | 24.28 | 0.186004 | 基线 |
| 全部追加 Prophet 候选后选型 | 2318.36 | 0.162718 | 12.52% |
| 原归一化收益/成本路由 | 429.27 | 0.186004 | 约 0% |
| 还原尺度收益/成本候选 | 481.55 | 0.163824 | 11.92% |

还原尺度候选的 memory_limit 平均窗口 RMSE 比快速基线降低约 1.24%；
CPU/request 与 CPU/limit 没有相对快速基线改善，不能声称所有指标都提升。
候选成本估算是快速基线约 19.8 倍，低于全部增强并不等于相对最便宜方案更省。

表中成本为串行模型阶段耗时合成估算，不是生产 CPU、费用或整个脚本的实测运行时长。
“79.2%”仅以全部增强为比较对象，不应写作“系统节省 79.2% 云资源”。
“11.92%”是 memory_request 指标平均窗口 RMSE 的相对下降，不是准确率提升 11.92 个百分点。

## 科研贡献的适当定位

1. 形成了资源—指标—窗口级的可追溯实验流程，使复杂模型增量收益与计算成本可以成对复核。
2. 在当前开发数据上识别出收益尺度与评价目标之间的敏感关系，为路由目标设计提供了实验线索。
3. 揭示了预算预测误差、反馈延迟及恢复探测之间的取舍，并通过本地反例与内网回放说明适用边界。

以上是本项目的工作贡献与经验发现，不等于已经通过完整文献查新或取得统计显著的算法先进性结论。

## 约一分钟汇报稿

我们的课题研究的是，在大量云资源同时预测时，怎样把有限计算优先分配给值得运行复杂模型的任务。
我们搭建了内网可运行的实验工具，所有原始数据留在内网，只导出汇总结果。
实验发现，复杂模型并非对所有序列都有益，快速模型本身是很强的基线。
进一步诊断发现，原路由的收益归一化口径影响了计算分配。
保持同一个收益模型、还原历史尺度后，内存 request 指标的 RMSE 相对快速组合降低约百分之十一点九二，
阶段计算成本估算比全部使用增强流程降低约百分之七十九点二。
这不是所有指标的全面提升，CPU 仍处于快速基线水平。
我们目前完成的是离线开发验证与候选方法，尚未证明生产费用节省或长期泛化，后续会以独立时间数据验证。

## 常见答辩问题

**是否已经上线？**
没有。平台原有功能与本次研究候选应分开描述，本次路由候选没有作为默认生产策略部署。

**为什么没有全部使用 Prophet？**
全部增强在部分内存指标上效果较好，但开销高。研究目标是在误差和计算之间选择合适取舍，
而不是假设复杂模型一定最好。快速基线同样必须保留。

**这些数据是独立验证吗？**
模型选型与测试按时间隔离，但这批结果被反复用于方法诊断，整体仍属于开发证据。
多次重新汇总不能当作多批独立验证，后续时间泛化尚未完成。

**79.2% 的节省是真实账单下降吗？**
不是。是相对全部增强流程的阶段耗时估算下降，尚未计入全部部署开销，也没有真实账单实验。

**方法有什么不足？**
跨指标效用尺度尚需业务定义，内存收益可能集中于少数资源；
精确起点未核对真实调度批次，成本反馈时机是假设；没有硬预算保证及长期稳定性证明。

**为什么没有完成更长时间实验？**
受本阶段时间约束，独立新时间段和生产实验保留为后续工作，并在结果中明确标注；
不将未完成内容包装成已验证结论。
